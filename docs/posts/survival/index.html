Abstract

Managing Non-Performing Loans (NPLs) requires accurate predictions of how long defaulted mortgages will remain in legal limbo. In our dataset of 4,872 foreclosure cases (2010–2020), 28% were still active at data cutoff, reflecting “live” files that have yet to conclude.

By combining classic Kaplan–Meier estimates and log-rank tests with both Cox Proportional Hazards and Cox Time-Varying models, we uncover which factors:

  • Speed up resolution (e.g., settlement agreements, specific legal stages, certain law firms)
  • Slow down closure (e.g., appeals, particular courts, regions)

These insights are critical for:

  • Valuing distressed assets more precisely
  • Allocating legal resources efficiently
  • Strategic decision-making in loan recovery processes

1. Introduction

Understanding how long foreclosure processes take—and why they vary—is crucial for NPL management and legal resource planning. This post:

  1. Explores case durations via Kaplan–Meier curves.
  2. Tests group differences (agreement vs. full foreclosure).
  3. Fits a CoxPH model to identify static covariate effects.
  4. Extends to a Cox Time‑Varying model to capture evolving factors across proceedings.

2. Dataset Overview

  • Size: 4,872 unique foreclosure files

  • Censoring: 28% of cases were still active (unresolved) at the end of the study period (censored), meaning no resolution date is recorded by Dec 2020

  • Time span: Jan 2010 – Dec 2020

  • Key fields:

    • case_id, start_date, end_date, time_to_event, event_observed
    • general_type (acuerdo vs. foreclosure vs. other)
    • region (ZoneA/B/C)
    • judicial_court (12 courts), law_firm (30 firms)
    • has_cassation (appeal indicator)

  • Preprocessing: dropped missing events, one‑hot encoded high‑cardinality columns with frequency threshold.

3. Model Descriptions

Before diving into results, here’s a quick overview of the models used:

  • Kaplan–Meier Estimator Non-parametric method to estimate the survival function \(S(t)\), i.e., the probability a case remains unresolved beyond time \(t\). Useful for visualizing overall duration and comparing groups via log-rank tests.

  • Cox Proportional Hazards (CoxPH) Model Semi-parametric regression that relates covariates to the hazard rate \(h(t)\). Assumes covariate effects are constant over time (proportional hazards). Provides hazard ratios to quantify how each feature speeds up or slows down resolution.

  • Cox Time‑Varying Fitter Extension of CoxPH allowing covariates to change at different time intervals (start–stop times). Captures dynamics within a case—e.g., when a new appeal is filed or the case moves to a different stage—thus modeling how evolving factors influence the instantaneous hazard.

4.2 Group Comparison (Log‑Rank Test)

results = logrank_test(
    df.query("general_type=='acuerdo'")['time_to_event'],
    df.query("general_type=='foreclosure'")['time_to_event'],
    event_observed_A=df.query("general_type=='acuerdo'")['event_observed'],
    event_observed_B=df.query("general_type=='foreclosure'")['event_observed']
)
print(results.p_value)

p < 0.001: median 10.5 mo (acuerdo) vs. 16.8 mo (foreclosure)

6. Time‑Varying Cox Model

6.1 Preprocessing for Time‑Varying Data

  • Calculated start/stop days since initial filing for each proceeding.
  • Created binary event per row.
  • One‑hot encoded categorical features (portfolio, stage, proceeding, resolution type, general type, zone, court, firm).

Feature Engineering

In this section, we prepare our categorical features for the Cox Time‑Varying Fitter model through one‑hot encoding. We focus on the following key features:

  • Portfolio Name
  • Legal Stage
  • Legal Proceeding
  • Resolution Type
  • General Type
  • Zone Group
  • Region
  • Clave
  • Judicial Court
  • Law Firm
# Identify categorical features
features = ['Portfolio Name', 'Legal Stage', 'Legal Proceeding',
            'resolution type', 'general type', 'zone group', 'region',
            'clave', 'Judicial Court', 'Law Firm']

# Determine significant categories (>=1% frequency)
from collections import Counter
significant = {f: [cat for cat, freq in Counter(df_processed[f]).items() if freq/len(df_processed)>=0.01]
               for f in features}

# One-hot encode each feature
from sklearn.preprocessing import OneHotEncoder
encoders = {}
for f in features:
    enc = OneHotEncoder(categories=[significant[f]], sparse=False, handle_unknown='ignore')
    encoders[f] = enc.fit(df_processed[[f]])
    cols = [f"{f}_{cat}" for cat in enc.categories_[0]]
    df_processed[cols] = enc.transform(df_processed[[f]])
    df_processed.drop(columns=[f], inplace=True)
    print(f"Encoded {len(cols)} categories for {f}")

7. Discussion & Conclusion

  • Static vs. dynamic models both highlight settlement type and appeals as dominant factors.
  • Time‑varying model uncovers how each proceeding’s context (stage, new appeals, firm interventions) shifts hazard rates.
  • Regional and institutional (court/firm) variations persist after adjustment.
